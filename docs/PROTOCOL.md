# ScreenLink 通信协议规范 v1.0

> 本文档是语言无关的协议规范，双端实现必须严格遵循。修改需同步双端。
> 关键词：MUST / MUST NOT / SHOULD / MAY（RFC 2119）

## 1. 总体设计

- **传输层**：TCP，电脑端监听 `8848` 端口（可配置，范围 1024-65535）
- **安全层**：TLS 1.3，电脑端为服务端持有证书，手机端为客户端校验并固定证书
- **应用层**：长度前缀帧（Length-Prefixed Framing），负载为 UTF-8 JSON 或二进制图片
- **拓扑**：手机主动连接电脑（电脑无需知道手机地址）；电脑端 MUST 支持多客户端同时连接（MVP 可仅单客户端）

## 2. 帧格式

```
+----------------+--------+------------------+
| Frame Length   | Type   | Payload          |
| 4 bytes BE     | 1 byte | N bytes          |
+----------------+--------+------------------+
```

- `Frame Length`：uint32 大端，**Payload 长度**（不含 4+1 字节头）
- `Type`：
  - `0x01` = JSON 控制帧（UTF-8）
  - `0x02` = 二进制数据帧（图片 JPEG）
- 最大帧长 64 MiB（超限断开并记录日志）

**所有帧均在 TLS 信道内传输，不存在明文帧。**

## 3. 证书与身份

### 3.1 服务端证书

- 电脑端首次启动 MUST 生成 ECC P-256 自签证书（有效期 365 天），存储于配置目录 `certs/`
- 证书到期前 7 天自动重新生成；重新生成后已配对手机需重新配对（指纹变更）
- 证书指纹 = SHA-256 摘要，十六进制小写表示，用于配对分发与客户端校验

### 3.2 客户端身份

- 手机端首次配对时生成随机 `device_id`（UUID v4）
- 手机端向电脑端注册：`device_id` + `device_name`（用户可改，如"我的小米14"）

## 4. 配对流程（P0）

> 目标：建立「手机 → 电脑」的信任关系，同时完成证书指纹分发。
> PIN 与二维码承载相同信息，只是输入通道不同。

### 4.1 电脑端发起

1. 用户在电脑端设置窗口点击「添加设备」
2. 电脑端生成配对码：`32 字节 CSPRNG → Base32 编码 → 8 位可读分组（XXXX-XXXX）`
   - 有效期 10 分钟；同时只允许 1 个活跃配对码（新生成使旧的失效）
   - 配对码校验失败计数：同一 IP 连续错 3 次 → 拉黑该 IP 5 分钟
3. 电脑端显示二维码（内容见 4.2）或 PIN 文本

### 4.2 二维码内容（V1.1）

```
screencap://pair?host=<电脑IP>&port=<端口>&code=<配对码>&fp=<证书SHA256指纹>
```

### 4.3 流程

```
手机                            电脑
 │  1. TCP 连接 + TLS 握手         │
 │     （校验证书指纹 == 配对码携带的 fp）│
 │  2. pair_request               │
 │  {type:"pair", code, device_id,│
 │   device_name}                 │
 │                               │ 3. 校验 code 有效且未过期
 │                               │    校验 device_id 未重复
 │  4. pair_response             │
 │  {type:"pair_resp", ok:true,  │
 │   server_id, server_name,     │
 │   allowed:true}               │
 │                               │ 5. 记录 device_id → 信任列表（persist）
 │  6. 手机记录服务器指纹+信息     │
 │     配对完成，进入会话流程      │
```

- 失败：`{type:"pair_resp", ok:false, code:1002, msg:"配对码错误"}`
- 已配对设备再次发 `pair`：MUST 拒绝（提示先删除旧记录或使用重连流程）

## 5. 会话流程（已配对设备重连）

```
手机                            电脑
 │  1. TCP + TLS（校验固定指纹）   │
 │  2. hello                     │
 │  {type:"hello", device_id}    │
 │                               │ 3. 查信任列表：存在 → 接受
 │  4. hello_ack                 │
 │  {type:"hello_ack", session_id│
 │   , server_name, presets:[...]│   ← 顺带下发区域预设列表
 │   , quality_max:100}          │
```

- 未知 device_id → `{type:"error", code:1001, msg:"未配对"}` + 断开
- 同一 device_id 重复连接：MUST 踢掉旧连接（后连优先）

## 6. 截图指令与回传（P0）

### 6.1 手机 → 电脑

```
{type:"capture", region:"fullscreen"|"<预设名>", quality:85}
```

- `quality`：JPEG 质量 1-100，缺省 85；电脑端 MAY 限制上限（config.quality_max）
- 电脑端串行处理截图请求（同一时间只处理一张）

### 6.2 电脑 → 手机

成功（JSON 帧先行）：
```
{type:"capture_resp", ok:true, width, height, size_bytes,
 region, ts: <unix毫秒>}
```
随后紧跟一个 `0x02` 二进制帧（JPEG 数据）。

失败：
```
{type:"capture_resp", ok:false, code, msg}
```
错误码：`1003` 预设不存在 / `1004` 无显示器 / `1005` 截图失败 / `1006` 编码失败

### 6.3 隐私约束（硬性）

- 电脑端 MUST NOT 在任何非 `capture` 指令期间采集屏幕
- 电脑端 MUST NOT 在本地持久化截图，除非用户配置了保存目录（PC-02）
- 截图仅经 TLS 信道发送，日志不记录图片内容

## 7. 心跳与断线

- 双方每 30s 发送 `{type:"ping"}`，对端回 `{type:"pong"}`
- 60s 无任何数据 → 判定断线，关闭连接
- 手机端重连策略：指数退避 1s/2s/4s...上限 30s，直到用户手动断开

## 8. 错误码总表

| code | 含义 |
|---|---|
| 0 | 成功 |
| 1001 | 未配对（device_id 不在信任列表） |
| 1002 | 配对码错误/过期 |
| 1003 | 区域预设不存在 |
| 1004 | 无可用显示器 |
| 1005 | 截图失败 |
| 1006 | JPEG 编码失败 |
| 1007 | 帧过大 / 格式非法 |
| 1008 | 请求过于频繁（限流） |

## 9. 安全设计清单

1. **传输加密**：TLS 1.3（禁 TLS <1.2），套件由系统默认安全策略决定
2. **证书固定**：手机端配对时记录服务器证书指纹，每次连接校验（防中间人）
3. **配对码**：32 字节 CSPRNG，10 分钟有效，3 次错误拉黑 IP 5 分钟
4. **防重放**：`capture` 帧携带 `seq`（uint32 递增），电脑端拒绝小于等于已处理序号的消息
5. **无明文泄漏**：整个链路无未加密帧；配置目录权限默认仅当前用户
6. **最小权限**：电脑端仅监听配置的端口；不开放任何其他服务
7. **自毁性**：删除配对记录即吊销；电脑端删除信任列表条目后，该手机立即无法连接

## 10. 版本与扩展

- 协议版本号在 `hello` 中携带：`proto:1`
- 版本不匹配：手机端 MUST 提示「电脑端协议版本不兼容，请升级」
- 扩展位：Type 0x03-0x0F 预留（V2 实时预览/录屏使用，帧结构不变）
